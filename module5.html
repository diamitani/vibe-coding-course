Understanding Context Windows and Token Limits

Every AI model has a context window — the amount of text it can process at once. Think of it as short-term memory. Everything in this window is available for the AI to consider when generating its response.

The challenge is that AI treats everything in its context with roughly equal attention, but it has a strong recency bias — it pays most attention to the beginning and end of the context. Information in the middle gets less weight.

The Context Curve

Research has shown that AI models have a U-shaped attention curve across their context window:

  • High attention: The first ~10% of your prompt (the most important position)
  • Medium attention: The last ~20% of your prompt
  • Low attention: The middle ~70% of your prompt ("lost in the middle" effect)

Practical Implication: Put your most important instructions at the very beginning of your prompt. Put your second-most important instructions at the very end. Put reference material and background information in the middle.

What Information Matters Most to AI

When engineering your context, prioritize what the AI needs to produce good results:

High Priority (Always Include)

  • Clear goal: What exactly do you want the AI to produce? Be specific.
  • Role/Persona: Who should the AI be? "You are a senior frontend developer specializing in React."
  • Constraints: What limits apply? "Must work without JavaScript. Must be responsive. Must load in under 2 seconds."
  • Output format: How should the result be structured? "Return a single HTML file. Use Tailwind CSS via CDN."

Medium Priority (Include When Relevant)

  • Reference code: Existing code the AI should follow or extend
  • Design preferences: Colors, layout, style guidelines
  • Brand guidelines: Fonts, logo placement, tone of voice
  • Technical context: Framework versions, dependencies, environment

Low Priority (Include Sparingly)

  • Background information: History, rationale, tangential context
  • Multiple examples: One good example beats three mediocre ones
  • Unnecessary code: Code that doesn't directly affect what you're building

Token Budget Rule: For a 200K context window, dedicate ~70% to the actual task, ~20% to reference material/examples, and keep ~10% for the AI's response. If you use more than 60% of the window, consider chaining instead.

Structuring Information for Clarity

How you structure your context matters as much as what you include. A well-structured prompt is significantly more effective than a messy one.

Recommended Structure

  • Role Definition — Who the AI is being
  • Goal Statement — What you want to achieve
  • Context/Bulleted Background — Key information the AI needs
  • Specific Instructions — Step-by-step what to do
  • Constraints & Requirements — Non-negotiables
  • Output Format — How to present the result
  • Examples (if needed) — Reference of good output

Use Formatting Liberally

AI models read formatting cues just like humans do. Use these techniques to improve clarity:

  • Headings (###, ##) to separate sections
  • Bullet points for lists of requirements
  • Bold text to emphasize key points
  • Code blocks to separate code from instructions
  • Horizontal rules to separate distinct sections
  • Numbered lists for sequential instructions

Prioritizing Content in Limited Context

When you're working within a tight context window (or when your project is large), you need to be strategic about what to include.

The TL;DR Technique

Start each section with a one-line summary, then add details. The AI will read the summary even if it skims the details. Example:

  • "Database schema: 4 tables (users, products, orders, reviews). Full schema below."
  • "The key constraint is auth — we use Supabase. Details follow."

The "Include On Request" Pattern

Don't include everything upfront. Tell the AI what's available and let it ask for what it needs:

  • "I have the full API documentation available. Ask me for specific endpoints as needed."
  • "The design system includes 40+ components. I'll share specific ones on request."

Compression Techniques

  • Remove comments: Strip comments from code examples
  • Use shorthand: "RSC" instead of "React Server Component"
  • Summarize: "Similar to Stripe's checkout flow" instead of describing the entire flow
  • Reference only relevant parts: Instead of including an entire file, include only the function signature and the specific lines that matter

Pro Tip: When sharing code, don't paste entire files. Paste the specific function or component with a brief description of its context. This saves tokens and helps the AI focus.

Prompt Templates That Work

Here are templates for common vibe coding scenarios. Adapt these to your needs:

Template: Build a Component

ROLE: Senior React Developer

GOAL: Build a [component name] component that [does what?]

CONTEXT:
- This is part of [project name], a [type of app]
- It will be used in [parent component or page]
- Uses [tech stack, e.g., React 18 + Tailwind + TypeScript]

REQUIREMENTS:
- Props: [list props and their types]
- States: [loading, empty, error, success states]
- Accessibility: [specific a11y requirements]
- Responsive: [breakpoint requirements]

OUTPUT: Return a single [filename].tsx file with full implementation

Template: Fix a Bug

ROLE: Senior Debugging Engineer

BUG: [describe what's happening vs what should happen]

REPRODUCTION:
1. [step to reproduce]
2. [step to reproduce]
3. [expected vs actual]

RELEVANT CODE:
[paste ONLY the relevant function/component — not the entire file]

CONSTRAINTS: [must not break X, must maintain Y, must work with Z]

Save Your Templates: Once you find a template that works, save it. Build a personal library of 5-10 templates covering your most common tasks. Good templates are force multipliers — they save time and improve quality on every project.

Good vs. Poor Context Engineering

Poor Context (Don't Do This)

"Hey can you make me a website? Like a landing page or something. Make it look nice. Use whatever colors. I need a form too I think. Just make something cool."

This prompt is vague, lacks structure, and gives the AI no useful constraints. The result will be generic and likely miss your actual needs.

Good Context (Do This)

"You are a senior frontend developer specializing in conversion-optimized landing pages.

Build a single-page landing page for 'FlowTrack' — a SaaS tool for freelancers to track invoices and expenses.

Key sections: Hero with headline/subtitle/CTA, Features (3 columns with icons), Pricing (3 tiers), Testimonials (carousel with 3 quotes), and Contact form.

Design: Professional dark theme (dark navy background, white text, accent color: #06b6d4 cyan). Modern, clean, with subtle animations.

Technical: Single HTML file. Tailwind CSS via CDN. No JS libraries. Responsive (mobile-first). Lighthouse score target: 90+.

Output the complete HTML file."

This prompt gives the AI role, goal, structure, design, technical constraints, and output format. The result will be dramatically better.

Iterative Context Refinement

Your first prompt is rarely your best. Here's how to refine:

The 3-Pass Refinement Process

  • Pass 1 — Draft: Write your prompt quickly. Don't overthink it. Get the basic idea down.
  • Pass 2 — Structure: Add formatting. Use headings, bullet points, and bold to organize the information. Check for clarity.
  • Pass 3 — Trim: Remove unnecessary words and information. Tighten your language. Every unnecessary word is a token that could be used for something more valuable.

Test and Adjust

Run your prompt through the AI. Review the output. Then refine the prompt based on what you got. This is the most effective way to improve your context engineering skills — you learn by seeing what works and what doesn't.

The Pareto Principle of Prompting: 80% of improvement comes from the first 20% of prompt refinement. Adding structure (headings, bullets, clear sections) creates the biggest quality jump. Don't spend hours perfecting a prompt that already produces acceptable results.

Exercises

📝 Exercise 1: Prompt Audit

Take a prompt you've used recently. Score it on: (1) Role defined? (2) Clear goal? (3) Structured formatting? (4) Constraints listed? (5) Output format specified? Then rewrite it with the missing elements and compare the results.

~20 minutes

🔧 Exercise 2: The 3-Pass Refinement

Write a prompt for a simple project (e.g., "build a weather dashboard"). Apply the 3-pass refinement: draft, structure, trim. Count the words in each version. Run all three versions through the same AI and compare the quality differences.

~30 minutes

📊 Exercise 3: Token Budget Practice

Take a project description for a medium-complexity app. Categorize each piece of information as high, medium, or low priority. If you had only 2000 tokens of context, what would you include and what would you leave out? Justify your decisions.

~20 minutes

📋 Exercise 4: Build a Template Library

Create 3 prompt templates based on this module: one for building a new component, one for debugging, and one for code review. Save them in a way you can reuse them. The next time you need one, it's ready to go.

~25 minutes
